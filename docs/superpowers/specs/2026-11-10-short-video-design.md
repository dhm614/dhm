# 短视频模块设计

## 目标

在现有宠趣社区中增加短视频功能。普通用户可以上传短视频，管理员审核通过后才公开展示。公开视频支持浏览器直接播放、进度拖动、点赞、收藏、举报和评论。管理员可以审核、删除和恢复视频。

本期仅支持 MP4，单个视频最大 100MB。不实现转码、压缩、清晰度切换、视频时长解析和真实推荐算法。

## 核心方案

短视频作为一种特殊类型的社区帖子保存，不单独建立点赞、收藏、评论和举报表。

在 `post` 表增加：

- `content_type`：内容类型，`POST` 表示普通帖子，`VIDEO` 表示短视频。
- `video_url`：MP4 文件地址，普通帖子为空。

继续复用 `post_like`、`post_collect`、`post_comment` 和内容举报数据。这样短视频与普通帖子拥有一致的互动规则，同时避免重复实现互动模块。

普通帖子查询必须固定过滤 `content_type = 'POST'`，短视频查询必须固定过滤 `content_type = 'VIDEO'`。社区列表、话题帖子列表和帖子搜索不得混入短视频。

## 状态规则

短视频沿用帖子状态：

- `0`：待审核。
- `1`：审核通过，可以公开查看和互动。
- `2`：已删除、驳回或下架，不在前台展示。

用户提交视频时，后端强制写入状态 `0`。公开列表和详情只返回状态 `1` 的视频。管理员可以将待审核视频设为 `1`，将视频设为 `2`，或者把已删除视频恢复为 `1`。

短视频的标题和简介继续经过现有敏感词检查。提交的话题必须是状态正常的已有话题。

## 后端组件

### 数据对象

- `Post` 增加 `contentType` 和 `videoUrl`。
- 新增 `ShortVideoCreateDTO`，字段为用户 ID、标题、简介、封面 URL、视频 URL 和话题。

### 用户接口

- `POST /api/videos`：提交短视频，返回待审核结果。
- `GET /api/videos`：查询审核通过的视频列表。
- `GET /api/videos/{id}`：查询审核通过的视频详情。

新增 `ShortVideoController` 和 `ShortVideoService`，底层使用现有 `post` 表。独立接口可以避免普通发帖接口通过客户端参数伪造内容类型。

点赞、收藏和评论继续使用现有帖子互动接口，参数中的帖子 ID 就是视频对应的 `post.id`。举报继续使用 `targetType = POST`，不增加重复的举报类型。

### 管理员接口

- 查询短视频审核与管理列表，可按状态筛选。
- 审核通过短视频。
- 删除或下架短视频。
- 恢复已删除短视频。

所有管理员视频接口必须继续校验 `X-User-Id` 对应管理员身份，不能只依赖前端隐藏按钮。

### 文件上传

封面使用单独的图片模块目录，视频使用 `short-video` 模块目录。

当上传模块为 `short-video` 时，后端必须同时校验：

- 文件扩展名为 `.mp4`。
- 文件大小不超过 100MB。

Spring Multipart 全局上限调整为允许 100MB 视频请求，业务服务仍执行模块级限制。其他图片和文档上传规则保持不变。

本地存储继续由 `/uploads/**` 静态资源映射提供文件。Spring MVC 静态资源处理器负责 HTTP Range 请求，前端 `<video>` 可以拖动播放进度。MinIO 模式使用对象存储公开 URL，由 MinIO 提供 Range 能力。

## 前端页面

### 短视频列表 `videos.html`

- 页面顶部提供“上传短视频”入口。
- 主区域只显示少量审核通过的视频卡片。
- 每张卡片只展示封面和标题。
- 点击卡片进入短视频详情页，不在列表页同时播放多个视频。

### 上传页面 `video-publish.html`

提交字段依次为：

- 标题文本。
- 封面图片。
- MP4 视频。
- 简介文本。
- 已审核话题标签选择。

封面和视频先调用文件上传接口获得 URL，再调用 `POST /api/videos` 提交业务数据。提交成功后显示“已提交管理员审核”，不直接出现在公开视频列表。

### 播放页面 `video-detail.html`

- 使用 `<video controls preload="metadata" poster="封面地址">` 播放 MP4。
- 播放器下方依次展示点赞、收藏、举报按钮。
- 互动区域下方展示评论列表和评论输入。
- 只有状态为 `1` 的视频可以打开详情和执行互动。

### 导航和后台

- 首页及公共顶部导航增加“短视频”入口。
- 后台管理页增加独立的“短视频审核与管理”区域。
- 后台列表显示 ID、标题、发布用户、状态和操作按钮。
- 操作按状态展示审核通过、删除和恢复。

## 数据流

1. 用户选择封面，前端上传到封面模块并获得封面 URL。
2. 用户选择 MP4，前端上传到 `short-video` 模块并获得视频 URL。
3. 前端提交标题、简介、封面 URL、视频 URL 和话题。
4. 后端校验用户、必填字段、话题和敏感词，写入 `post`，内容类型为 `VIDEO`，状态为 `0`。
5. 管理员审核通过后状态变为 `1`，视频进入公开列表。
6. 播放页直接把视频 URL 交给浏览器，浏览器通过 Range 请求按需读取 MP4。
7. 点赞、收藏、举报和评论使用视频对应的帖子 ID 进入现有互动流程。

## 错误处理

- 缺少标题、简介、封面、视频或用户 ID 时拒绝提交。
- 话题不存在或未审核通过时拒绝提交。
- 上传文件不是 MP4 或超过 100MB 时拒绝上传。
- 视频不存在或未审核通过时，公开详情返回统一业务错误。
- 非管理员调用审核、删除和恢复接口时拒绝操作。
- 文件上传成功但业务提交失败时，本期不自动删除孤立文件，沿用项目现有上传策略。

## 数据库迁移

主建表脚本与独立迁移脚本同时更新：

```sql
ALTER TABLE post
    ADD COLUMN content_type VARCHAR(20) NOT NULL DEFAULT 'POST' COMMENT 'POST普通帖子 VIDEO短视频',
    ADD COLUMN video_url VARCHAR(500) NULL COMMENT '短视频MP4地址',
    ADD INDEX idx_post_content_status_time (content_type, status, create_time);
```

现有数据依靠默认值统一视为普通帖子。

## 测试与验收

后端测试覆盖：

- 视频提交后状态为待审核，内容类型为 `VIDEO`。
- 公开视频列表只返回状态 `1` 的视频。
- 普通帖子列表、话题帖子列表和帖子搜索不返回视频。
- 视频标题和简介执行敏感词校验，话题必须有效。
- 管理员审核、删除和恢复权限正确。
- 非 MP4 和超过 100MB 的 `short-video` 上传被拒绝。
- 已审核视频可以复用点赞、收藏、举报和评论。

前端静态检查覆盖：

- 三个视频页面存在并带正确页面标识。
- 公共导航包含短视频入口。
- 上传页面限制 `.mp4`。
- 播放页面使用 HTML5 视频控件。
- 后台包含视频审核、删除和恢复操作。

运行验证覆盖：

- 后端编译和测试通过。
- 前端 JavaScript 语法检查通过。
- 将前端同步到 Tomcat 后，页面可从 `http://localhost:8081/petcommunity/videos.html` 访问。
- 对本地视频 URL 发送带 `Range` 的请求，确认服务返回分段响应。

## 不在本期范围

- 视频转码、压缩、切片和多清晰度播放。
- HLS、DASH、CDN 和防盗链。
- 视频时长、分辨率和编码格式解析。
- 自动抽帧生成封面。
- 推荐算法、播放量统计和自动连播。
