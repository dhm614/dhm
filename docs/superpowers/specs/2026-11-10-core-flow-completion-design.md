# 宠趣社区核心流程补全设计

## 目标

本轮补全以下五项功能：

1. 用户预约状态跟踪和商户预约处理。
2. 后台举报处理与评论管理。
3. 关注、取消关注、关注列表和粉丝列表。
4. 数据统计看板增强展示。
5. 对上述功能补充后端权限测试和前端静态检查。

地图 API 和 MinIO 运行配置不属于本轮范围，等本轮功能验收完成后再处理。

## 实现原则

- 沿用当前 Spring Boot、MyBatis-Plus、原生 HTML/CSS/JavaScript 结构。
- 不新增数据库表，不修改现有字段含义。
- 页面显示文本使用中文。
- 权限必须由后端校验，前端隐藏只用于改善操作体验。
- 尽量复用现有接口、DTO、VO 和 `app.js` 请求封装。
- 商城仍为模拟结算，不引入真实支付。

## 预约流程

### 用户预约页面

新增 `my-appointments.html`，从个人主页进入。页面调用当前用户预约列表接口，展示预约 ID、门店、服务项目、宠物、预约时间、备注和状态，并允许取消处于“已预约”状态的记录。

前端不能通过输入用户 ID 查询其他用户预约。后端从 `X-User-Id` 确认当前操作者，并要求其与被查询或取消预约的用户一致。

### 商户预约页面

新增 `merchant-appointments.html`，仅已审核商户和管理员可进入。商户先选择自己拥有的门店，再查看该门店预约。允许把有效预约更新为已完成或已取消。

权限规则：

| 操作 | 普通用户 | 商户 | 管理员 |
|---|---|---|---|
| 创建自己的预约 | 允许 | 允许 | 允许 |
| 查看自己的预约 | 允许 | 允许 | 允许 |
| 取消自己的预约 | 允许 | 允许 | 允许 |
| 查看门店预约 | 禁止 | 仅自己的门店 | 全部门店 |
| 完成或修改预约状态 | 禁止 | 仅自己的门店 | 全部预约 |

`AppointmentController` 的创建、用户列表、门店列表、取消、完成和状态修改接口统一读取 `X-User-Id`。`AppointmentService` 在修改状态前查询预约和门店，调用现有管理员判断和门店归属判断逻辑。

## 后台审核增强

### 评论管理

在 `admin.html` 增加评论管理区域，调用现有 `/api/admin/audit/comments` 接口。每条评论显示评论 ID、帖子 ID、用户 ID、内容和状态，并提供隐藏或恢复操作。

### 举报处理

举报列表显示举报对象、原因、状态和处理结果。待处理记录提供“举报成立”和“举报驳回”操作，两者都要求填写处理说明。

举报成立后，普通帖子状态设置为 `3`，表示管理员下架；不能设置为 `2`，因为 `2` 表示审核驳回。评论仍使用状态 `0` 表示隐藏。举报驳回不修改目标内容。

管理员操作完成后刷新举报和评论列表。

## 关注与粉丝

继续使用现有 `profile.html` 作为用户主页。页面通过 URL 参数 `userId` 或页面输入框确定被查看用户，并把当前登录用户作为 `viewerId` 请求 `/api/users/{id}/profile`。

查看其他用户主页时，根据 `followedByViewer` 显示“关注”或“取消关注”，操作成功后刷新主页。查看自己的主页时不显示关注按钮。

主页增加关注列表和粉丝列表区域，分别调用现有 `followings` 和 `followers` 接口。列表展示用户 ID、用户名、昵称，并提供打开该用户主页的链接。

## 数据统计看板

继续使用 `/api/statistics/dashboard` 一次性获取数据，不增加重复接口。`dashboard.html` 增加以下区域：

- 今日活跃用户、今日发帖、今日预约、今日订单、今日订单金额。
- 预约完成率和用户预约转化率。
- 热门商品 TOP10。
- 热门帖子排行。
- 预约状态分布。
- 订单状态分布。
- 保留现有最近七日趋势和通知列表。

数据为空时显示空状态，不使用模拟统计数据替代接口结果。

## 页面入口

- `profile.html` 增加“我的预约”入口。
- 商户在 `services.html` 的商户管理区域增加“预约处理”入口。
- 管理员继续通过 `admin.html` 管理评论和举报。
- 普通用户不能看到商户预约处理入口，非管理员不能进入后台页面。

## 错误处理

- 后端权限失败统一抛出明确中文错误，例如“无权查看该门店预约”。
- 前端沿用 `request()` 的错误提示机制，将后端消息显示在页面通知区域。
- 状态更新失败时不提前修改页面数据，接口成功后重新加载列表。

## 测试与验收

### 后端测试

- 普通用户不能查看其他用户预约。
- 商户不能查看或处理其他商户门店预约。
- 商户可以查看和处理自己门店预约。
- 管理员可以查看和处理全部预约。
- 举报成立后帖子状态为管理员下架状态 `3`。
- 举报驳回后目标内容状态不变。

### 前端检查

- `my-appointments.html` 和 `merchant-appointments.html` 存在并注册页面初始化逻辑。
- 个人主页包含关注、取消关注、关注列表和粉丝列表逻辑。
- 后台包含评论隐藏/恢复和举报成立/驳回操作。
- 统计看板包含转化率、热门商品、热门帖子和状态分布容器。
- `app.js` 通过 Node.js 语法检查。
- 所有前端文件同步部署到 Tomcat `webapps/petcommunity`。

## 不在本轮范围

- 高德地图、百度地图或其他地图 SDK。
- 浏览器自动定位。
- MinIO 服务部署、密钥配置和存储类型切换。
- Elasticsearch。
- 数据库结构调整。
